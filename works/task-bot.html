チームタスク管理・
自動通知システム

Slackチャンネルへの手動投稿とスレッド返信で回っていたリモートチーム（8名規模）のタスク管理を、 Notionデータベースと自動通知Botに一本化。毎朝の報告作業をゼロにし、 優先度・進捗・負荷を誰からも見える状態にしました。

担当範囲：企画・設計・実装・運用（個人開発）

  • Python
  • Notion API
  • Slack API
  • Google Calendar API
  • GitHub Actions
  • matplotlib

01課題と解決アプローチ

Before — 手動運用の限界

  • 毎朝リーダーが日付をチャンネルに手動投稿し、各自がスレッドでその日のタスクを返信
  • タスクの優先度・期日・進捗がどこにも構造化されて残らない
  • 誰にどれだけ仕事が偏っているか（負荷）が見えない
  • メンバー増加とともに、スレッドを遡って状況を把握するコストが増大

After — 一元管理と自動化

  • タスクはNotionデータベースで一元管理（優先度・期日・ステータス・完了見込み日）
  • Botが毎朝、各自のSlack DMへ「今日の予定＋タスク」を自動配信
  • チャンネルには全員分のサマリーと電話当番を自動投稿し、手動投稿を廃止
  • 週次レポート（グラフ付き）を自動生成し、チームの実績を定点観測

04主な機能

☀️

朝の個人DM通知

毎朝、各メンバーのSlack DMへその日のカレンダー予定と未完了タスク（期日・優先度順）を配信。カレンダーの「休み」予定を検知した日は自動でスキップ。

📢

チャンネル自動投稿

全メンバーの予定・タスク・休みと「本日の電話当番（午前／午後）」を1本にまとめてチャンネルへ投稿。従来の手動投稿運用を置き換え。祝日は全通知を自動停止。

📈

リーダー向けサマリー

期日超過タスクだけを抽出したチームサマリーをリーダーへ毎朝DM。フォローが必要なメンバーが一目で分かる。

🔔

担当割り当て通知

Notionでタスクの担当者が設定されると、5分以内に本人へDM。夜間（22時〜8時）の割り当ては翌朝8時以降にまとめて送る配慮つき。

✅

完了通知

タスクが完了になると依頼者とリーダーへ自動DM。依頼者＝担当者（自己完結）なら送らない等、関係性に応じた宛先ロジックを実装。

📊

週次レポート自動生成

毎週土曜、完了実績のグラフ（matplotlib）付きNotionページを自動作成し、リンクをSlackへ配信。期限切れ率の前週比較も表示。

07技術的な工夫

⏰ 通知時刻の安定化

GitHub Actionsのcronは混雑時に1時間以上遅延する。実測した遅延幅から逆算して設定時刻を前倒しし、狙いの時刻に届くよう調整した。

🌙 夜間の通知抑制

担当割り当て通知は5分間隔のポーリングだが、22時〜8時に検知した分は翌朝8時以降にまとめて送信。リモートワークの生活リズムを壊さない設計にした。

🔁 冪等な通知（二重送信防止）

「通知済み」チェックボックスをNotion側に持たせ、ポーリングが何度走っても同じ通知が二度飛ばない構造にした。

🧩 スキーマ変更に強い判定

「進行中（25%/50%/75%）」等のサブステータス追加に備え、オプション名の文字列一致ではなくNotionのステータスグループAPIで判定。運用側が選択肢を増やしてもコード修正不要。

🎯 関係性に応じた宛先ロジック

完了通知は「依頼者＝担当者なら送らない」「依頼者未設定ならリーダーのみ」など4分岐で設計し、通知疲れを防いだ。

🔐 シークレット管理

APIトークン類はすべてGitHub Secretsで管理し、コード・チャット上に一切残さない運用を徹底。

08進め方と成果

1

要件定義
現行運用の課題を分解し、通知の粒度・タイミングを設計

2

実装・検証
まず自分1人で運用し、通知内容と時刻を調整

3

段階導入
メンバーを1人ずつ追加し、到達確認をしてから次へ

4

チーム展開
会議で実物をデモして合意形成し、旧運用を廃止

  • 毎朝の手動投稿・スレッド返信によるタスク報告を廃止し、報告作業の時間をゼロに
  • 優先度・期日・進捗・負荷がNotion上で常に可視化され、リーダーの状況把握が数分で完了
  • マネージャー向けには週次レポートのみ届ける等、役割に応じた通知設計で通知疲れを回避
  • GitHub Actionsの無料枠内で完結し、ランニングコスト0円で運用継続中
